# Runbook — v0.5.0 live cut-over (operator-executed steps)

**Context.** Release v0.5.0 ("clean restart of infra, CI and Databricks
artifacts") landed all code, tests and docs on `develop`. A subset of **live**
steps could not be executed by the implementing session because its action
policy gates resource deletion and `terraform apply` against real backends —
they are recorded here, in order, with their preconditions and proofs. Every
step is idempotent; nothing here touches anything owned by `dd-chain-capture`
(`capture/ecr` state key, `alias/dd-chain-capture-ssm`, Roles Anywhere,
`dd-chain-capture-*` ECR repos), the SSM parameters, the raw/lakehouse
buckets, the prd/dev Lambdas or the DynamoDB tables.

Already done by the release session (proofs in `TASKS.md`): the 2 stale state
locks are removed; the 4 `AWS_DEPLOY_ROLE_*` repository variables are published;
the static `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` and 5 capture-era secrets
are deleted; the CI user's 2025 access key is `Inactive`; 26 leaked/legacy
security groups and the 4 subnets of the legacy VPC are gone; the empty HML ECS
cluster is deleted; all 7 Databricks bundles are deployed to `dev` and `hml`.

Conventions: run from the repo root on `develop` (or `main` after cut-over),
`export TF_DATA_DIR=/tmp/tf-<stack>` per stack so `.terraform/` never lands in
the tree, `TF_IN_AUTOMATION=1`.
